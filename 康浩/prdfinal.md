
  

律所官网 + 轻 CMS 系统 PRD

  

  

  

Project overview

  

  

  

项目背景

  

  

当前项目是一个中文律所官网，已有核心栏目为：

  

- 关于我们
- 专业团队
- 专业资讯
- 专业研究
- 加入我们

  

  

网站的主要目标不是传统获客型企业站，而是优先塑造高端、克制、可信赖的律所品牌形象，并通过团队与内容输出来支撑专业度。整体视觉方向已明确为：

  

- 白色大背景
- 深蓝为主品牌色
- 浅灰 #F2F2F2 为辅助色
- 简洁、明亮、理性、有秩序感
- 素材图偏概念化、抽象化
- 字体、比例、留白需严格规范，视觉比例可参考方达一类大型律所官网

  

  

  

项目目标

  

  

本项目的目标优先级为：

  

1. 品牌展示
2. 专业内容输出
3. 轻度招聘承接

  

  

  

产品定位

  

  

建设一个具有“大所气质”的中文律所官网，并配套一个轻量 CMS 后台，用于维护官网内容，实现可持续运营。

  

  

产品范围

  

  

本期产品包含两部分：

  

1. 官网前台
2. 后台内容管理系统（CMS）

  

  

  

本期边界

  

  

本期只做中文站，不做中英文双语；不做复杂权限；不做站内简历投递；不做搜索、标签、分类体系；不做 AI 功能。

  

  

  

  

Core requirements

  

  

  

1. 品牌表达要求

  

  

网站必须体现以下品牌特征：

  

- 克制、高级、专业、可信
- 用排版、留白、节奏建立质感，而不是靠堆视觉元素
- 避免传统企业站式的信息堆叠
- 避免具象办公场景、握手、会议等俗套素材
- 避免资讯门户化、博客模板化、招聘平台化

  

  

  

2. 信息架构要求

  

  

网站主导航固定为：

  

- 关于我们
- 专业团队
- 专业资讯
- 专业研究
- 加入我们

  

  

要求：

  

- 极简导航
- 不做下拉菜单
- 不做复杂层级

  

  

  

3. 首页要求

  

  

首页需承担两个核心任务：

  

- 第一时间建立品牌信任感
- 通过团队与内容展示真实专业性

  

  

首页采用品牌驱动型结构，模块优先级为：

  

1. Opening Animation
2. Hero 首屏
3. 关于我们
4. 专业团队精选
5. 专业资讯
6. 专业研究精选
7. 加入我们
8. Footer

  

  

  

9. 内容系统要求

  

  

内容分为两类：

  

- 专业资讯：轻内容，更新更频繁
- 专业研究：重内容，数量较少，深度更强

  

  

要求：

  

- 资讯与研究必须分为两个独立栏目
- 两者均不分类、不打标签
- 均按发布时间倒序展示

  

  

  

5. 团队展示要求

  

  

专业团队是网站核心资产之一，要求：

  

- 团队列表页采用极简卡片墙
- 团队成员进入独立详情页
- 每位成员有照片、姓名、职位、简介、PDF 简历等结构化信息
- 团队照片必须风格统一

  

  

  

6. 招聘要求

  

  

加入我们页面定位为轻招聘页，要求：

  

- 展示岗位列表
- 展示岗位职责与要求
- 提供公司邮箱
- 不做站内简历提交
- 不设计简历投递后端流程

  

  

  

7. CMS 要求

  

  

系统必须具备一个轻量 CMS 后台，支持管理：

  

- 关于我们
- 团队成员
- 专业资讯
- 专业研究
- 招聘岗位
- 网站基础信息
- 文件资源（PDF、图片）

  

  

后台只需：

  

- 单管理员登录
- 不做多角色权限管理

  

  

  

8. 视觉系统要求

  

  

需要严格的设计规范，包括：

  

- 字号体系
- 行高体系
- 间距体系
- 栅格体系
- 图片风格统一规则
- 按钮、卡片、列表等组件规范

  

  

  

  

  

Core features

  

  

  

1. Opening Animation

  

  

官网进入时展示开场动画，建立品牌仪式感。

  

要求：

  

- 时长克制
- 动效简洁
- 支持跳过
- 不影响首屏体验

  

  

  

2. Hero 首屏

  

  

首屏采用极简品牌型表达，核心元素包括：

  

- 品牌标语
- 抽象动态背景
- 极少量辅助文字

  

  

已确认标语：

  

在不确定中，提供确定性的法律解决方案

  

  

3. 关于我们

  

  

首页与独立页面都需要关于我们模块，但表达重点不同：

  

- 首页：品牌宣言型表达
- About 页面：完整承接品牌表达

  

  

要求：

  

- 保持克制
- 不做普通公司简介式堆砌
- 提供“律所详情”PDF 下载按钮

  

  

  

4. 专业团队

  

  

包括两部分：

  

  

团队列表页

  

  

- 极简卡片墙展示

团队详情页

5. 专业资讯

  

  

包括：

  

  

资讯列表页

  

  

- 展示标题、日期、摘要、封面图
- 按发布时间倒序

  

  

  

资讯详情页

  

  

- 展示正文内容
- 维持良好阅读体验
- 可选上一篇/下一篇

  

  

  

6. 专业研究

  

  

包括：

  

  

研究列表页

  

  

- 展示标题、日期、摘要

- 律所名称

- 联系邮箱
- 电话

App/user flow

  

  

  

1. 官网访客流

  

  

  

场景 A：潜在客户

  

  

1. 用户进入首页
2. 先看到 Opening Animation
3. 进入 Hero 首屏，建立第一印象
4. 下滑浏览关于我们，形成初步品牌认知
5. 浏览团队精选，判断专业度
6. 浏览资讯/研究，判断持续专业输出能力
7. 查看完整团队或具体律师详情
8. 通过联系方式或进一步资料完成信任建立

  

  

  

场景 B：合作方 / 企业法务

  

  

1. 用户进入首页或直接进入团队页/研究页
2. 重点查看团队详情页与研究内容
3. 下载 PDF 简历或律所详情资料
4. 建立机构层面的合作认知

  

  

  

场景 C：求职者

  

  

1. 用户进入首页或加入我们页面
2. 浏览律所品牌形象
3. 查看岗位列表
4. 通过页面提供的公司邮箱投递简历

  

  

  

5. 后台管理员流

  

  

  

团队管理流

  

  

1. 管理员登录后台
2. 进入团队管理
3. 新增/编辑成员
4. 上传照片与 PDF 简历
5. 设置排序与发布状态
6. 前台自动展示更新结果

  

  

  

内容发布流

  

  

1. 管理员进入资讯或研究管理
2. 新建文章
3. 填写标题、摘要、正文、发布时间
4. 上传封面图或附件
5. 保存草稿或发布
6. 前台对应列表与详情页更新

  

  

  

招聘更新流

  

  

1. 管理员进入岗位管理
2. 新增/修改岗位
3. 设置岗位职责、要求、地点、邮箱
4. 发布后在加入我们页面展示

  

  

  

站点设置流

  

  

1. 管理员进入站点设置
2. 更新律所基础信息
3. 上传新的律所详情 PDF
4. 前台 Footer 和下载入口同步更新

  

  

  

  

  

Techstack

  

  

  

前台

  

  

Next.js

  

原因：

  

- 适合官网和内容站
- SEO 友好
- 团队、资讯、研究详情页路由自然
- 便于后续扩展

  

  

建议方向：

  

- App Router
- 服务端渲染/静态生成混合
- 支持响应式布局

  

  

  

后台/API

  

  

FastAPI

  

原因：

  

- 开发效率高
- 适合轻 CMS
- 文件上传、登录鉴权、内容管理都足够
- 便于后续接搜索、AI、知识库能力

  

  

  

数据库

  

  

PostgreSQL

  

原因：

  

- 稳定
- 与 FastAPI 生态成熟
- 适合结构化内容模型

  

  

  

文件存储

  

  

建议分阶段：

  

- 开发期：本地文件存储
- 正式期：MinIO 或 S3 兼容对象存储

  

  

  

鉴权

  

  

单管理员后台，采用以下任一方案即可：

  

- Session
- JWT

  

  

  

前端样式与组件

  

  

建议：

  

- Tailwind CSS 或 CSS Modules
- 设计变量统一管理
- 动效可使用 Framer Motion 或轻量 CSS 动效

  

  

  

富文本

  

  

后台文章正文建议采用：

  

- Markdown 编辑器  
    或
- 轻量富文本编辑器

  

  

重点不是编辑器花哨，而是内容输出稳定。

  

  

部署

  

  

建议：

  

- 前台与后台分离部署
- 使用 Nginx 反向代理
- 前台、后台、数据库、对象存储可容器化

Additional dimensions you may have overlooked

  

  

下面这些维度，你前面已经部分碰到，但还值得明确写进 PRD，否则后面很容易出问题。

  

  

1. 内容治理

  

  

不是只有“能发内容”就够了，还要明确：

  

- 谁来写资讯
- 谁来审核
- 资讯和研究的写作风格是否统一
- 标题、摘要、发布时间是否有规范
- 封面图是否允许为空

  

  

否则 CMS 建好了，内容风格也可能很乱。

  

  

2. 图片治理

  

  

你已经明确要统一图片风格，但建议继续落实为规则：

  

- 团队照片裁切比例统一
- 团队背景尽量统一
- 内容配图统一为抽象/概念化
- 禁止临时随手上传杂图

  

  

否则视觉系统会被内容运营逐步破坏。

  

  

3. 非功能需求

  

  

建议写入实施标准：

  

- 首屏加载性能
- 动效降级策略
- 手机端可读性
- SEO 基础配置
- 图片压缩和缓存策略

  

  

  

4. 可扩展性

  

  

虽然本期不做，但结构应预留未来扩展空间：

  

- 双语
- 搜索
- 标签
- AI 问答
- 内容推荐
- 更多栏目

  

  

你已经选了 Next.js + FastAPI + PostgreSQL，这套组合天然适合后续扩展。

  

  

5. 数据模型规范

  

  

建议尽早确定：

  

- slug 生成规则
- 发布时间规则
- 草稿/发布规则
- 删除是硬删除还是软删除
- 排序字段是否统一

  

  

否则后期联调会频繁返工。

  

  

6. 上线后的维护责任

  

  

建议在 PRD 里补一段运营责任说明：

  

- 谁维护团队信息
- 谁更新内容
- 谁上传 PDF
- 谁管理招聘岗位
- 谁负责发现线上错误

  

  

否则系统上线后很容易失控。

  

  

7. 法务与合规

  

  

这是律所官网，需额外注意：

  

- 团队简介与执业信息的准确性
- 文章内容表述的审慎性
- 联系方式、地址等信息的一致性
- PDF 资料版本一致性
